| | Detail |

### Bug 2 — Flaky randomness (`test_flaky_timing.py`)

| | Detail |

| **Symptom** | `assert random.random() > 0.3` fails ~30 % of runs non-deterministically |

| **Fix** | Replaced global `random.random()` with a locally-seeded `random.Random(42).random()` — seed 42 always produces `0.6394…`, which is unconditionally `> 0.3` |

## Error: `no_associated_service_instance_error`

```
project_id bd58bd97-35eb-4e02-b9f0-a7c254492833 is not associated with a WML instance
```

This is an **IBM Cloud configuration problem**, not a code bug. The Watson Machine Learning (WML) service instance has not been associated with your Watson Studio project.

---

## What causes it

Watson Studio projects and Watson Machine Learning are **two separate services** on IBM Cloud. To call foundation models via `watsonx.ai`, the project must have a WML service instance explicitly linked to it. Your project `bd58bd97-35eb-4e02-b9f0-a7c254492833` currently has no WML instance attached — so IBM Cloud rejects the request with a `403`.

---

## How to fix it

**Step 1 — Make sure you have a WML instance**
1. Go to [IBM Cloud Resource List](https://cloud.ibm.com/resources)
2. Under **AI / Machine Learning**, look for a **Watson Machine Learning** instance.
3. If none exists, click **Create resource** → search "Watson Machine Learning" → create one (the Lite/free tier is fine for testing).

**Step 2 — Associate the WML instance with your project**
1. Open [watsonx.ai](https://dataplatform.cloud.ibm.com)
2. Navigate to your project → **Manage** tab → **Services & integrations**
3. Click **Associate service** → select your WML instance → click **Associate**

**Step 3 — Re-run the test**
```powershell
$env:WATSONX_API_KEY="<your-key>"
$env:WATSONX_PROJECT_ID="bd58bd97-35eb-4e02-b9f0-a7c254492833"
python test_watsonx.py
```

## Quick checklist

| Check | What to verify |
|---|---|
| WML instance exists | IBM Cloud resource list shows a **Watson Machine Learning** service |
| WML instance is in same region | Must be **us-south** to match your URL |
| Project has WML linked | Project → Manage → Services & integrations shows WML |
| API key has access | The API key owner has at least **Editor** role on the WML instance |

The most common root cause is simply that the WML instance was never linked — Step 2 above fixes it in under a minute.
